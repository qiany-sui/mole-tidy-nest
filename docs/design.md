# SwiftUI＋AppKit＋Mole 适配层：设计确认与接口契约

> 本文保留历史设计及后续阶段补充，部分建议和协议草案已被替代。当前协作规则与实现边界见 [AGENTS.md](../AGENTS.md)，后续验收见 [历史验收记录](verification-history.md)。本文不构成新的实施或真实数据操作授权。

核对日期：2026-09-07。定位：先个人自用，之后可开源。用户已确认技术路线；本文确定开发依据，不代表 App 已实现。

## 1. 确认结论

这条技术路线可行。本机具备开发工具，原生界面 API 编译检查和限定示例目录的 Mole JSON 查询均通过。

主要工作在清理与卸载接口，而不在界面框架。原版 Mole 的预览输出不能直接作为可重放的执行计划。完整 GUI 必须增加明确的扫描计划与执行接口，并保留上游已有的路径保护、归属检查和运行状态检查。

首个开发里程碑应为：原生窗口、依赖检测、应用列表、应用详情、磁盘查询结果及错误状态。真实清理计划预览在第二个里程碑随扩展引擎交付；不得通过解析原版 dry-run 提前冒充结构化计划。启用破坏性操作前完成隔离测试。只读里程碑不等于整个需求完成。

## 3. 产品范围与页面规格

### 3.1 首批执行范围建议

- 清理：先支持经过逐项审计、能形成明确文件计划的普通用户缓存和日志规则。
- 卸载：支持可精确识别的普通应用或已知 iPhone/iPad 包装应用的外层本体，以及能验证归属的缓存、日志普通文件。包装应用只在 Containers 归属元数据可完整核验且唯一时读取 Data/Library/Caches、Data/Library/Logs；文稿、存档所在的 Documents/Application Support、偏好及共享容器保留。
- 已卸载应用残留：只有应用缺失、归属可信且共享状态可验证时才提供执行；否则仅展示并默认保留。
- Homebrew 应用可列出来源，但在独立卸载动作协议完成之前，不启用自动卸载。不得调用整体命令后仍承诺“只删勾选文件”。
- 系统级文件、活跃或无法确认稳定的目录、共享数据、符号链接、SQLite 数据、包管理器清理、模拟器和系统快照暂不进入首批执行规则。

上述限制是建议的首批范围，不是永久排除相关功能。每增加一类，必须同时补齐计划描述、执行约束和对应验证。

### 3.2 应用外壳

建议 macOS 14+，优先验证当前 arm64 设备。SwiftUI 负责导航、表格、状态与确认页；AppKit 负责应用图标、Finder 定位和必要的系统交互。

导航保留清理、应用卸载、磁盘分析、操作记录四个入口；设置通过 macOS 设置窗口进入。主窗口采用侧栏、结果列表、详情三栏结构。界面支持系统浅深色、键盘操作和 VoiceOver。每次启动固定进入应用页，不记住上次页面；普通依赖检测仅在侧栏显示进度与取消，不挤动主内容，异常与安装进度仍明确提示。恢复上次应用列表并检查依赖，切到应用页后可查看缓存，只有用户点击读取或刷新后才查询；列表注明完整列表更新时间，刷新失败或取消保留旧结果。应用详情另提供单项刷新，读取选中应用的当前名称、标识和占用，仅更新该记录，不改变完整列表时间。缓存中的应用可直接检查移除计划，不要求本会话先刷新，也不自动追加列表或单项刷新；列表仅用于选择目标，维护引擎独立核验当前路径、标识、安装集合与保护规则。应用/磁盘查询可与维护检查并行，记录读取独立；同类请求、实际执行和退出收尾仍保留互斥。磁盘与维护扫描仍由用户主动选择。

维护检查使用横向流动进度条，阶段文案说明读取应用信息、当前应用名称与序号、最终状态复核和结果整理；扫描总量未知时不显示整体百分比。执行阶段按所选项目已收到的独立结果显示「已处理 x / n 项」，失败、保留与取消结果同样计入处理数量。全部项目收到结果后仍等待最终结果，不提前宣布完成；取消期间保持已有结果和处理数量。

没有活动任务时不常驻扫描、不启动定时清理、不创建 root helper。系统状态监控和其他 Mole 命令不属于首个里程碑。

### 3.3 清理页

| 状态 | 页面内容 | 可执行操作 |
|---|---|---|
| 未扫描 | 扫描范围与权限说明 | 开始扫描 |
| 扫描中 | 当前阶段、已发现数量、可用的大小统计 | 取消扫描 |
| 扫描完成 | 分组列表；名称、占用、识别理由、处理方式、可选状态 | 勾选、查看详情、长期保护、检查计划 |
| 扫描不完整 | 可读取范围的结果，以及未扫描范围与原因 | 审查可信项目；补权限后重新扫描 |
| 等待确认 | 已选目标、永久删除与废纸篓分类、影响说明 | 返回修改、明确确认 |
| 执行中 | 当前动作、逐项结果；总量未知时不显示百分比 | 请求取消后续动作 |
| 执行结束 | 成功、跳过、失败、取消或待核对项目 | 查看日志、重新扫描 |

首次扫描默认不勾选，用户自行选择。右侧详情必须提供完整路径、大小是否已知、识别依据、处理方式和预期影响。“本次不选”只更新当前选择；“长期保护”才写入 App 的保护配置。检查提示使用整行按钮展开/收起，文字、箭头和留白都可点击，提供明确状态；新计划重置为折叠。 展开内容优先使用实际高度，超过 120 点时改为滚动；路径与原因按条分组，不用空白撑开短提示，不截断长提示。

底部显示“已选占用”，不能将所有选中大小统称“预计释放”。结果分别报告永久删除的估算占用、移入废纸篓的估算占用和观察到的磁盘空闲变化；后者可能受到其他进程和文件系统影响。

### 3.4 应用卸载页

应用列表展示图标、名称、安装路径、来源和可用大小。搜索只过滤界面列表，绝不把搜索词直接作为卸载命令参数。

选定应用后，以安装路径为主标识，bundle ID 和应用身份信息用于复验。详情分为应用本体、可选用户残留、共享或受保护项目。应用本体是执行卸载任务的必选项，界面默认勾选，但可撤回选择；取消本体同时取消依赖残留并使旧确认失效，重新勾选不自动恢复残留。未选本体时不能确认卸载任务。仅清理残留使用清理任务，避免两种语义混合。

扫描不完整、应用仍运行、同标识应用安装集合变化、应用身份变化时，展示原因并重新审查。首版不自动强制退出应用。应用列表出现同名 App 时，路径必须可见。

App 本体移动、残留删除、登录项处理、偏好域修改和包管理器卸载属于不同动作。若不能精确列出和执行这些动作，就不显示“完整卸载”成功。

### 3.5 磁盘分析页

用户明确选择目录后查询。首版采用按大小排序的列表、面包屑、子目录下钻和 Finder 定位；树图可在数据链路稳定后增加。

已有 JSON 字段通过独立解码器映射，不把 display size 字符串当作原始字节值。大小未知与零大小分开。缺省的 `large_files` 可按空列表显示，但其他字段缺失仍应按协议要求检查。

首版磁盘页仅查询和定位；通用文件删除不与“缓存清理”共用一个无约束删除入口。

### 3.6 操作记录与设置

记录任务标识、时间、命令种类、引擎版本、用户确认范围、逐项结果及诊断原因。日志留在本机，默认不上传；不记录密码。导出日志必须是用户主动操作。

设置展示可执行路径、版本、兼容状态、相关权限和 App 保护规则。原版 Mole 白名单可只读继承；App 自身规则保存在独立配置中。旧计划绑定最终生效配置，任一保护规则变化后须重新扫描。

## 4. 已有 Mole 接口的真实边界

| 能力 | 1.53.0 现状 | 适配决策 |
|---|---|---|
| analyze | `mole analyze --json <path>`；示例查询实测通过 | 使用独立 JSON 解码器 |
| uninstall --list | 非 TTY stdout 自动 JSON；字段 name、bundle_id、source、uninstall_name、path、size | 仅用于列表；严格检查退出码和 JSON；不把名称作为执行身份 |
| status/history | 文档支持 JSON，本轮未运行 | 后续按需接入，不能标为本轮实测通过 |
| clean --dry-run | 文本清单加内部 NUL 分隔候选账本 | 内部账本可作为扩展线索，不能直接视为执行计划 |
| clean 分类选择 | 当前明确拒绝 --select、--categories、--exclude | 不依赖这些参数 |
| uninstall 按名称执行 | 首个精确同名匹配，或多个子串匹配 | GUI 禁止据此执行所选应用 |
| dry-run | 可能写清单、日志、扫描缓存，部分路径仍交互 | 不作为 App 的纯扫描 API |
| clean 废纸篓模式 | 缓存路径不使用统一 Trash 路由 | 每个规则明确动作，不能通过环境变量统一宣称可恢复 |
| Homebrew 卸载 | 可执行 --zap，成功后还可能后台 autoremove | 独立动作协议审计前不启用；禁止隐式 autoremove |

普通应用列表成功输出不必然被 ANSI 污染，但失败分支可能写文本到 stdout；现有手写 JSON 转义与内部路径分隔也不是稳定协议。原版兼容层应遇到异常即报告无法解析，不能从损坏文本猜出待删除目标。

## 5. 适配层与扩展引擎

### 5.1 责任分工

1. UI：展示、选择、用户确认，不持有任意命令执行能力。
2. 任务管理：串行协调维护检查与执行，保存状态和逐项结果。只读检查可与应用列表/单项刷新或磁盘查询并行。记录读取拥有独立任务与 Bridge 客户端，取消只影响自身；扫描期间允许精确 ID 的记录删除，晚到结果按现有 tombstone 合并。实际执行仍等待查询、记录读取及取消收尾结束；退出先禁止派发并取消只读任务，再等待各任务结束。
3. 原版适配器：发现明确路径的本机 Mole；核对版本；只调用已支持的查询接口，分别捕获 stdout、stderr 和退出码。
4. 扩展引擎：基于固定的 Mole 代码版本，复用规则及保护逻辑，增加计划与执行接口。独立于 Homebrew 安装，不覆盖用户的 mole/mo。

原版适配器是验证及查询入口；扩展引擎是完整清理功能的必需部分。先提交上游或保留小范围补丁都可以，但不能把“等上游合并”当作唯一可执行路线。若复用范围不断扩张，应重新评估维护成本。

使用明确的可执行路径和独立 argv 数组，设置必要环境。GUI 启动不能依赖交互 shell 的 PATH。不得拼接任意 shell 字符串，不通过替换 HOME 改变配置位置和清理目标。

M1 实现采用 posix_spawn 显式建立独立进程组。通过 waitid 的 WNOWAIT 观察退出，在管道读取或取消收尾完成前保留子进程 PID，最后再 waitpid 回收，避免父进程快速退出后的 PID 复用风险。App 退出时先取消并等待所有查询收尾。这是对原 Foundation Process 方案的实现调整，不改变只读命令边界。M2 的执行取消协议仍需单独实现与验证。

首版不引入本地 HTTP 服务、通用插件系统或任意命令终端。App 与引擎直接通过管道通信。

### 5.2 新协议 v1（拟新增，不是现有 Mole 参数）

扩展引擎提供五类入口：`capabilities`、`list-apps`、`scan-clean`、`plan-uninstall`、`apply-plan`。入口使用固定参数，结构化输入经 stdin 传递。

| 请求 | 输入 | 输出 |
|---|---|---|
| capabilities | 无 | schemaVersion、engineVersion、engineDigest、rulesVersion、支持的规则及动作 |
| list-apps | 明确的应用扫描范围 | 应用记录、扫描完整性、未扫描范围 |
| scan-clean | scopeRoots、ruleIds、有效保护配置 | 进度事件和完整 ScanPlan |
| plan-uninstall | appPath、预期 bundle ID、有效保护配置 | 应用身份、关联关系及 ScanPlan |
| apply-plan | planId、selectedItemIds、确认信息 | 逐项结果和最终 ApplyResult |

查询型入口 stdout 为单份 JSON。扫描与执行 stdout 全程为 NDJSON；stderr 仅为诊断文本，不参与业务状态判断。每条事件包含 `schemaVersion`、`runId`、递增 `sequence`、`type` 和 `payload`。最后必须有一条 `result` 事件。

事件类型：`progress`、`candidate`、`itemResult`、`result`。candidate 可渐进展示，但只有收到最终计划后才能确认执行；最终计划允许明确记录漏扫范围，不能把尚未结束的扫描当成可执行计划。读取器按字节缓存完整行，再做 UTF-8/JSON 解码；中文、换行文件名在 JSON 内正确转义，不按显示文本拆路径。

协议版本不兼容时禁用执行。显示名称、stdout 文案、文件路径都不能充当可信执行命令。

### 5.3 ScanPlan

| 字段 | 类型与语义 |
|---|---|
| schemaVersion | 整数；v1 为 1 |
| planId / runId | 不透明标识；项目 ID 只在本计划内有效 |
| engineVersion / engineDigest / rulesVersion | 固定执行器与规则身份 |
| configurationDigest | 扫描时最终生效的保护配置摘要 |
| createdAt / scopeRoots | 生成时间与授权扫描根目录 |
| scanComplete / scanIssues | 是否完整；拒绝访问、跳过范围及原因 |
| appIdentity | 卸载任务使用：应用路径、bundle ID、应用及 Info.plist 身份、包内成员快照摘要、同标识安装集合摘要 |
| items | 候选动作记录 |

每条候选动作包含：`itemId`、`ruleId`、`path`、`parentIdentity`、`targetIdentity`、`kind`、`action`、`estimatedBytes`、`sizeBasis`、`reason`、`impact`、`requiredPermission`、`selectability`、`guardPolicy`、`dependsOnItemIds`。整目录移动额外包含 `memberManifestDigest`，对应引擎保存的完整成员快照。

- action 首批仅开放经过实现与验证的 `deleteFile`、`trashItem`、`removeEmptyDirectory`。对尚未支持的系统服务或包管理器动作，标记不支持，不假装转换成文件删除。
- 身份至少包含设备号、inode、文件类型和变化信息；读取时不跟随符号链接。大小未知使用 null，不能填 0。
- selectability 区分可选、任务必选和禁止选择；被保护项带原因。卸载残留动作依赖应用本体动作，依赖项目必须同在计划和选择集合内。
- 清理列表可按目录分组，但确认授权落到扫描时明确列出的对象。不得在 apply 阶段重新展开 glob 或新增递归目标。

计划保存在 App 私有目录，不能直接执行用户提供或修改过的任意 JSON 文件。引擎从自己的计划存储解析 planId，并再次验证根目录、规则和路径允许范围。

### 5.4 执行约束

- 接受的只有当前有效计划内的项目 ID；未知 ID、引擎变化、配置变化、计划已消费或身份不符时拒绝。
- 引擎拒绝遗漏任务必选项、选择禁止项或缺少依赖的请求。卸载时先处理应用本体，本体成功后才处理依赖残留；本体失败、跳过或取消时，这些残留不执行，并返回依赖未完成的原因。
- GUI 只负责传递选择；规则、身份、权限和运行状态均由引擎再次检查。
- 执行仅遍历已选项目，不运行完整 clean/uninstall 来间接实现选择。
- 对目录的选择不能授权删除扫描之后新增的内容。缓存操作按已枚举对象处理，目录仅在确认为空时移除。
- 所有整目录 trashItem（包括 App 包和残留目录）都绑定完整成员快照：相对路径、类型、对象身份、大小与变化信息。执行前比较成员集合及身份，新增、替换或变化后须重新审查；只检查目录或 Info.plist 的 stat 不够。App 包还须检查安装集合及运行状态；无法确认稳定的包不执行。不能用这些检查宣称完全消除了检查与操作之间的竞态；系统调用级边界必须在启用执行前专项审查。
- 运行状态检查分别报告应用/包内 helper 运行与外部程序占用，提示包含名称、PID、访问方式和文件路径。整包本体可容忍已确认外部进程的数字文件描述符、只读、无锁普通文件访问；目录句柄即使标为只读仍能以 openat 写成员，继续保留。写入、锁、txt/mem 等映射、未知或不完整记录均不放行；缓存/日志的所有相关占用继续阻止处理。lsof 以 NUL 分隔字段，其路径转义按字节只解码一次再验证范围，兼容 Finder 启动时缺少 locale 和中文路径。
- 计划中的占用是检查时的快照，不监听并自动重扫。用户可「重新检查此应用」，沿用上一次的精确目标，由引擎生成新计划，旧选择与确认作废；失败或取消后仍可重试，普通清理检查不沿用旧应用。
- 失败不得从废纸篓静默降级为永久删除。保留系统实际返回的废纸篓路径。
- 同一用户只允许一个扩展引擎执行修改任务；锁在引擎中实现，覆盖多窗口、多实例和直接调用扩展 CLI。原版 Mole 不一定参与此锁，因此不能宣称已防住原版 CLI 并发，仍须逐项重验。
- 不自动执行 --zap、autoremove、强制退出、退出后的重新发现目标或其他未列入计划的附带动作。

### 5.5 取消、失败与结果

执行状态包括：`completed`、`partial`、`cancelled`、`blocked`、`failed`。应用端另保留 `unknown`，用于进程异常结束且没有最终结果的情况。

建议扩展协议退出码：0 完成；2 部分完成；3 需要重新审查或权限阻塞；4 失败；130 已响应取消。原版 Mole 的退出码由原版适配器单独解释，不能套用新协议。

取消通道为 App 对当前扩展引擎调用 Process.interrupt() 发送 SIGINT。引擎捕获信号、设置取消标志，界面进入 cancelling；不启动新的动作，已开始的动作在安全边界结束并记账，随后发出 cancelled 结果并退出 130。App 同时等待最终事件与进程退出；取消不等于撤销。

正常取消不自动升级为强杀。引擎未响应时，用户可明确选择“强制结束”，界面说明当前动作结果可能无法确认；先发 SIGTERM，5 秒后仍未退出再终止本任务进程组。进程组必须由任务管理器明确创建和记录，不依据名称查找或终止其他进程。没有最终结果的在途项目标记待核对，禁止自动重试删除。

关闭窗口时若正在执行，应让用户明确选择等待或取消任务；App 退出后不遗留计划外后台清理。Process.terminate 仅发送 SIGTERM，不能将调用返回等同于引擎已经停止。

ApplyResult 包含每项的结果、原因、可用的实际废纸篓位置及计量口径。终端退出码、最终事件和项目结果不一致时显示协议错误或待核对，不能弹出成功提示。

## 7. 权限与分发

首版以普通用户权限运行。拒绝访问时明确标出未扫描范围，分别解释完全磁盘访问、应用管理权限和传统文件权限。不给通用 shell 请求完全磁盘访问，不把 root 当作绕过隐私保护的方法。

真实权限验收必须从 Finder 启动具有稳定签名身份的 App，而不是只在 Terminal/Xcode 下运行。当前工具链编译检查不能证明此链路已经可用。

确需系统级动作后，再评估 SMAppService 管理的受限辅助程序与 XPC。XPC 自身不是提权。正式向其他用户分发时再完成 Developer ID、Hardened Runtime、公证和新机器 Gatekeeper 验收；这些不是当前已完成项。

开源发布使用独立品牌。基于 Mole 修改和分发的代码按实际许可证要求保留来源和许可；官方 App 的品牌与资源不能视为 Mole 开源代码的一部分。

## 8. 开发顺序与验收门槛

M2 的首批实现细化见 `docs/m2-plan.md`：固定 Mole 规则与保护子集在 Swift 中移植，原文摘录随引擎保留；首批动作收窄为移入废纸篓。CLI/界面继续保持独立计划、确认与执行边界。标准目录与执行过程中可观察的身份变化必须复验，系统调用不能冻结同 UID 的并发写者，该边界不能用测试通过掩盖。

M2 实际接口、动作与大小上限以该实现计划为准；上文协议表是早期设计，`deleteFile` 和 `removeEmptyDirectory` 未开放。应用归属核验限固定 Mole 的 8 个安装根目录及 `/Volumes`，不扫描桌面、下载目录，也不作全磁盘唯一性的承诺。运行状态检查不能排除支持范围外的未启动副本。

| 里程碑 | 交付 | 必须通过的验收 |
|---|---|---|
| M1 原生查询 | 窗口、依赖检测、应用列表及详情、磁盘分析与错误状态 | Finder 启动；同名应用显示路径；空列表、损坏 JSON、权限不足均不误报成功；不启用删除，不提供虚假清理计划 |
| M2 计划预览与执行 | 固定版本扩展引擎；清理计划页面；首批缓存、普通应用与残留规则 | 未选文件内容和存在性不变；新增文件不被纳入；身份/共享/配置变化拒绝；必选项与依赖校验；本体失败后残留不执行；特殊路径不变成命令；取消和部分失败正确记账 |
| M3 自用稳定与开源准备 | 真实设备验证、兼容说明、来源许可、分发包 | macOS 最低版本实机验证；引擎升级兼容；签名公证；干净账户和新机器验收 |

M2 测试只能使用明确的隔离目录、测试 App 包和可控进程。不得把真实个人缓存或已安装软件当作自动化删除测试对象。Homebrew/系统级功能需要另有动作契约及验证后才能启用。
